# Arena Companion
## 4-Page Submission Plan for Assignment A1

## Goal
Turn the detailed product document into a compact, visual submission that stays within four pages and avoids becoming a text-heavy report.

## Page 1 - Concept and Context

### Main Purpose
Introduce the product idea and explain why it matters.

### Include
- Product title: Arena Companion
- One-sentence concept statement
- Short problem statement
- Target users
- Context of use
- Simple product vision

### Suggested Visuals
- One central mobile mockup
- A sticky-note style concept summary
- User icons for volunteers, shift leaders, and arena staff

## Page 2 - Scenarios and Features

### Main Purpose
Show how the product works in practice.

### Include
- Volunteer journey from arriving at the arena to completing a task
- Core scenarios:
  - start shift
  - navigate
  - check in
  - receive alert
  - report incident
- Prioritized features
- Why mobile technologies are relevant

### Suggested Visuals
- Journey line or flowchart
- Small feature cards with icons
- Labels connecting features to GPS, map, camera, QR, notifications, and offline support

## Page 3 - Data, Ecosystem, and Feasibility

### Main Purpose
Demonstrate technical understanding.

### Include
- Core data objects
- What data comes from API
- What data is stored locally
- Offline and sync logic
- Recommended technology stack
- Authentication and login logic
- Why a backend database is needed
- Key risks and technical challenges

### Suggested Visuals
- Small ecosystem diagram
- Data grouping table
- Simple architecture diagram: mobile app + backend + local storage
- Login flow sketch: user -> auth -> token -> app session
- Offline sync sketch
- Risk box with 4 to 6 key concerns

## Page 4 - MVP and Semester Roadmap

### Main Purpose
Show that the idea is realistic and can be developed step by step.

### Include
- MVP definition
- Essential vs optional features
- Semester timeline
- Implementation direction for the chosen stack
- Open questions for later discussion

### Suggested Visuals
- Timeline from A1 to final prototype
- MVP box and extension box
- Small stack note or technical decision box
- Open questions note in the corner

## Writing Style Recommendations

- Keep paragraphs short
- Prefer short blocks, labels, diagrams, and annotations
- Explain relationships, not just lists
- Show why each feature belongs in a mobile app
- Briefly justify why the selected stack fits a semester project
- Use captions to connect visuals and technical reasoning

## Compression Rule

If a section becomes too text-heavy, convert it into one of these:
- a table,
- a feature-to-technology matrix,
- a user journey,
- a data flow diagram,
- or a grouped set of sticky notes.

## Recommended Workflow

1. Finalize the detailed product document
2. Reduce each section into keywords and short explanations
3. Assign the content to the four pages above
4. Sketch page layouts
5. Produce the final visual submission
