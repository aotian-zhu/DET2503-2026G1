## Test isolation and environment corrections

UI tests use an isolated cache file and controlled weather/account boundaries; they do not reset a volunteer's real snapshot or repeatedly call live auth/weather services. The separate login-screen test checks configured form callbacks; it does not authenticate real volunteer credentials. The outbox device test uses actual AtomicFile IO with a deliberately controlled service, not a deployed Supabase account. Normal application startup uses the real configured services.

The API 37 preview emulator and the host experienced memory pressure during concurrent compilation/emulation. One test process was terminated with Android's LOW_MEMORY exit reason, and an asynchronous UI save exceeded the initial 5-second wait. Compilation and emulator validation were separated; cached guest processes were released, software graphics/small display were used, and asynchronous assertions allow 15 seconds. A nearest-task assertion was corrected to scroll and inspect unmerged text inside its clickable card. Behavioral assertions remain in place. These environment/test-harness corrections are not described as physical-phone observations.

The Windows build helper now reads JDK release metadata rather than interpreting java -version's stderr as an error in Windows PowerShell. Its verification run uses a single-use Gradle daemon so completed builds do not hold the log open or compete with the emulator.
