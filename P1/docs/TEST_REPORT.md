## Issues found and resolved

- The initial computer setup had no SDK 35 installation and used an incompatible newer JDK for the A2 wrapper. SDK 35/build tools were installed for verification; the project documents compatible JDKs.
- Host memory pressure caused an emulator System UI dialog. Completed build daemons were stopped, Gradle memory/concurrency was reduced and the temporary emulator display was resized. This was an environment problem, not an app crash.
- The API 37 System UI startup dialog recurred during the repository-update check. All eight application tests completed successfully; the system dialog was dismissed and the temporary read-only emulator was closed after testing.
- On 13 October, opening the saved emulator from the launcher produced a black screen and an unresponsive Android System UI. Switching its graphics mode from auto to software and forcing a cold boot restored rendering without wiping app data. The patched application was installed and its real launcher/login screens were inspected, followed by nine successful device tests.
- Old Espresso input injection was incompatible with the installed Android API. Espresso 3.7.0 and compatible AndroidX test libraries resolved it. [AndroidX Test release notes](https://developer.android.com/jetpack/androidx/releases/test).
- Returning from a denied-permission dialog replaced the specific denial notice with general guidance. The map now preserves the denial notice and opens app permission settings when appropriate.
- Switching map layers kept the task list's previous scroll position, hiding the first facility. The list now focuses its selection or returns to the start when the layer/order changes.
- Two temporary Gradle transformation-cache entries failed to move on Windows during a rebuild. Only those generated cache entries were cleared; the subsequent build passed.

## Boundaries of the evidence

Live Supabase authentication, live incident-photo upload/RPC submission, push notifications and a real camera scan have **not** been verified against the group's service/device. The supplied QR and demo-checkpoint action support the student walkthrough. Backend outbox tests are controlled tests, not claims about a deployed service. Optional photographs and persisted document-picker access should be checked on the group's physical phone before recording that part.

There are no known crashes in the tested P1 flows after the corrections above. This is evidence for the stated emulator configuration, not every Android device/API/accessibility setting. Offline coverage guarantees operational data and GPS calculations; it does not guarantee unvisited OSM imagery.

The API 37 emulator sometimes resumed slowly during screen recording.
